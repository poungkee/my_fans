## 데이터베이스 개요

### 기본 정보

- **DBMS**: PostgreSQL 15+
- **인코딩**: UTF-8
- **타임존**: Asia/Seoul (KST)
- **총 테이블 수**: 15개
- **총 인덱스 수**: 22개
- **트리거 수**: 8개
- **뷰 수**: 3개

### 확장 기능

```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";  -- UUID 생성
CREATE EXTENSION IF NOT EXISTS "pg_trgm";    -- 텍스트 검색 최적화
```

### 테이블 분류

| 분류 | 테이블 수 | 테이블 목록 |
|------|---------|------------|
| **마스터 테이블** | 4 | users, sources, categories, keywords |
| **뉴스 관련** | 2 | news_articles, news_keywords, raw_news_articles |
| **사용자 활동** | 3 | user_actions, bookmarks, comments |
| **통계 및 집계** | 1 | article_stats |
| **AI 분석** | 3 | bias_analysis, ai_recommendations, user_preferences |
| **기타** | 1 | market_summary |

## 테이블 상세 설계

### 1. 마스터 테이블

#### 1.1 users (사용자)

**용도**: 사용자 정보 및 인증 관리

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| id | BIGSERIAL | PK | 사용자 ID |
| username | VARCHAR(50) | NOT NULL, UNIQUE | 사용자명 |
| email | VARCHAR(100) | NOT NULL, UNIQUE | 이메일 |
| password_hash | VARCHAR(255) | NOT NULL | 비밀번호 해시 (bcrypt) |
| user_name | VARCHAR(100) | - | 실명 |
| tel | VARCHAR(20) | - | 전화번호 |
| profile_image | VARCHAR(500) | - | 프로필 이미지 URL |
| active | BOOLEAN | DEFAULT true | 활성 여부 |
| provider | VARCHAR(20) | DEFAULT 'local' | 인증 제공자 (local/kakao/naver) |
| social_token | VARCHAR(500) | - | 소셜 로그인 토큰 |
| previous_pw | VARCHAR(255) | - | 이전 비밀번호 (보안) |
| last_login | TIMESTAMPTZ | - | 마지막 로그인 |
| created_at | TIMESTAMPTZ | DEFAULT NOW() | 생성일 |
| updated_at | TIMESTAMPTZ | DEFAULT NOW() | 수정일 |

**인덱스**:
```sql
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_active ON users(active);
CREATE INDEX idx_users_provider ON users(provider);
```

**예시 데이터**:
```sql
INSERT INTO users (username, email, password_hash, provider)
VALUES ('홍길동', 'hong@example.com', '$2b$12$...', 'kakao');
```

### 2. 뉴스 관련 테이블

#### 2.1 news_articles (뉴스 기사)

**용도**: 최종 처리된 뉴스 기사

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| id | BIGSERIAL | PK | 기사 ID |
| title | VARCHAR(500) | NOT NULL | 제목 |
| content | TEXT | - | 본문 |
| ai_summary | TEXT | - | AI 생성 요약 |
| url | VARCHAR(1000) | UNIQUE | 원문 URL |
| image_url | VARCHAR(1000) | - | 대표 이미지 |
| source_id | INTEGER | FK → sources | 언론사 ID |
| category_id | BIGINT | FK → categories | 카테고리 ID |
| journalist | VARCHAR(100) | - | 기자명 |
| pub_date | TIMESTAMPTZ | - | 발행일 |
| created_at | TIMESTAMPTZ | DEFAULT NOW() | 생성일 (크롤링일) |
| updated_at | TIMESTAMPTZ | DEFAULT NOW() | 수정일 |
| search_vector | tsvector | - | 전문 검색 벡터 |

**인덱스** (7개):
```sql
CREATE INDEX idx_news_source_id ON news_articles(source_id);
CREATE INDEX idx_news_category_id ON news_articles(category_id);
CREATE INDEX idx_news_pub_date ON news_articles(pub_date DESC);
CREATE INDEX idx_news_created_at ON news_articles(created_at DESC);
CREATE INDEX idx_news_search_vector ON news_articles USING GIN(search_vector);
CREATE INDEX idx_news_journalist ON news_articles(journalist) WHERE journalist IS NOT NULL;
```

**제약 조건**:
- `url` UNIQUE → 중복 기사 방지
- `source_id` FK → ON UPDATE CASCADE
- `category_id` FK → ON UPDATE CASCADE

**트리거**:
```sql
-- search_vector 자동 업데이트
CREATE TRIGGER trigger_search_vector
    BEFORE INSERT OR UPDATE ON news_articles
    FOR EACH ROW EXECUTE FUNCTION update_search_vector();
```

#### 2.2 raw_news_articles (크롤링 원본)

**용도**: 크롤링 직후 원본 저장 (AI 처리 전)

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| id | BIGSERIAL | PK | 원본 ID |
| title | VARCHAR(500) | NOT NULL | 제목 |
| content | TEXT | - | 본문 |
| url | VARCHAR(1000) | UNIQUE | 원문 URL |
| image_url | VARCHAR(1000) | - | 이미지 |
| original_source | VARCHAR(100) | - | 언론사명 (텍스트) |
| original_category | VARCHAR(50) | - | 카테고리명 (텍스트) |
| journalist | VARCHAR(100) | - | 기자명 |
| pub_date | TIMESTAMPTZ | - | 발행일 |
| crawled_at | TIMESTAMPTZ | DEFAULT NOW() | 크롤링일 |
| processed | BOOLEAN | DEFAULT FALSE | AI 처리 완료 여부 |

**처리 흐름**:
```
1. 크롤러 → raw_news_articles 저장 (processed=FALSE)
2. 스케줄러 → AI 처리
3. 분류 완료 → news_articles로 이동
4. processed=TRUE 업데이트
```

#### 2.3 news_keywords (뉴스-키워드 관계)

**용도**: M:N 관계 테이블

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| news_id | BIGINT | FK → news_articles | 기사 ID |
| keyword_id | BIGINT | FK → keywords | 키워드 ID |
| relevance | DOUBLE PRECISION | DEFAULT 1.0 | 관련도 (0.0~1.0) |

**복합 PK**:
```sql
PRIMARY KEY (news_id, keyword_id)
```

### 3. 사용자 활동 테이블

#### 3.1 user_actions (통합 사용자 행동 로그)

**용도**: AI 추천을 위한 사용자 행동 데이터

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| id | BIGSERIAL | PK | 행동 ID |
| user_id | BIGINT | FK → users | 사용자 ID |
| article_id | BIGINT | FK → news_articles | 기사 ID |
| action_type | VARCHAR(20) | CHECK | VIEW/LIKE/DISLIKE/BOOKMARK |
| reading_duration | INTEGER | - | 읽은 시간 (초) |
| reading_percentage | INTEGER | CHECK (0~100) | 읽은 비율 (%) |
| weight | DOUBLE PRECISION | DEFAULT 1.0 | 가중치 |
| created_at | TIMESTAMPTZ | DEFAULT NOW() | 행동 시간 |

**제약 조건**:
```sql
-- action_type 제한
CHECK (action_type IN ('VIEW', 'LIKE', 'DISLIKE', 'BOOKMARK'))

-- 중복 방지 (VIEW 제외)
CONSTRAINT uk_user_article_action UNIQUE (user_id, article_id, action_type)
```

**인덱스** (5개):
```sql
CREATE INDEX idx_user_actions_user_id ON user_actions(user_id);
CREATE INDEX idx_user_actions_article_id ON user_actions(article_id);
CREATE INDEX idx_user_actions_type ON user_actions(action_type);
CREATE INDEX idx_user_actions_created ON user_actions(created_at DESC);
CREATE INDEX idx_user_actions_user_time ON user_actions(user_id, created_at DESC);
```

**action_type 설명**:
- **VIEW**: 기사 조회 (여러 번 가능)
- **LIKE**: 좋아요 (1번만)
- **DISLIKE**: 싫어요 (1번만)
- **BOOKMARK**: 북마크 (1번만)

#### 3.2 bookmarks (북마크)

**용도**: 사용자 북마크 (호환성 유지)

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| id | BIGSERIAL | PK | 북마크 ID |
| user_id | BIGINT | FK → users | 사용자 ID |
| news_id | BIGINT | FK → news_articles | 기사 ID |
| created_at | TIMESTAMPTZ | DEFAULT NOW() | 북마크 시간 |

**제약**:
```sql
CONSTRAINT uk_user_bookmark UNIQUE (user_id, news_id)
```

**자동 동기화**:
```sql
-- bookmarks 테이블과 user_actions 동기화
CREATE TRIGGER trigger_bookmark_sync
    AFTER INSERT OR DELETE ON bookmarks
    FOR EACH ROW EXECUTE FUNCTION sync_bookmark_actions();
```

### 4. 통계 및 집계 테이블

#### 4.1 article_stats (기사 통계)

**용도**: 기사별 통계 (성능 최적화)

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| article_id | BIGINT | PK, FK → news_articles | 기사 ID |
| view_count | BIGINT | DEFAULT 0 | 조회 수 |
| like_count | BIGINT | DEFAULT 0 | 좋아요 수 |
| dislike_count | BIGINT | DEFAULT 0 | 싫어요 수 |
| bookmark_count | BIGINT | DEFAULT 0 | 북마크 수 |
| comment_count | BIGINT | DEFAULT 0 | 댓글 수 |
| updated_at | TIMESTAMPTZ | DEFAULT NOW() | 업데이트 시간 |

**자동 업데이트 트리거**:
```sql
-- user_actions에서 자동 집계
CREATE TRIGGER trigger_stats_from_actions
    AFTER INSERT OR DELETE ON user_actions
    FOR EACH ROW EXECUTE FUNCTION update_article_stats();
```

**조회 예시**:
```sql
-- 인기 기사 TOP 10
SELECT a.title, s.view_count, s.like_count
FROM news_articles a
JOIN article_stats s ON a.id = s.article_id
ORDER BY s.view_count DESC
LIMIT 10;
```

### 5. AI 분석 테이블

#### 5.1 bias_analysis (편향성 분석)

**용도**: AI 기반 편향성 분석 결과

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|

| bias_score | NUMERIC(3,2) | - | 편향 점수 (-1.00 ~ +1.00) |
| political_leaning | VARCHAR(50) | - | 정치 성향 (진보/중도/보수) |

| analysis_data | JSONB | - | 전체 분석 데이터 |
| created_at | TIMESTAMPTZ | DEFAULT NOW() | 분석일 |
| updated_at | TIMESTAMPTZ | DEFAULT NOW() | 수정일 |

CREATE INDEX idx_bias_article ON bias_analysis(article_id);

#### 5.2 ai_recommendations (AI 추천)

**용도**: 사용자별 기사 추천 (선택적)

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| id | BIGSERIAL | PK | 추천 ID |
| user_id | BIGINT | FK → users | 사용자 ID |
| article_id | BIGINT | FK → news_articles | 추천 기사 ID |
| recommendation_score | DECIMAL(4,2) | CHECK (0~99.99) | 추천 점수 |
| recommendation_reason | JSONB | - | 추천 이유 |

| was_clicked | BOOLEAN | DEFAULT false | 클릭 여부 |
| was_read | BOOLEAN | DEFAULT false | 읽음 여부 |
| feedback_score | INTEGER | CHECK (-1/0/1) | 피드백 점수 |

```sql
CONSTRAINT uk_user_article_recommendation UNIQUE (user_id, article_id)
```

#### 5.3 user_preferences (사용자 선호도)

**용도**: AI 학습용 사용자 프로필

| 컬럼명 | 타입 | 제약 | 설명 |
|--------|------|------|------|
| user_id | BIGINT | PK, FK → users | 사용자 ID |
| preferred_categories | JSONB | - | 선호 카테고리 |
| preferred_keywords | JSONB | - | 선호 키워드 |
| preferred_sources | JSONB | - | 선호 언론사 |
| age | INTEGER | CHECK (0~150) | 연령 |

## 트리거 및 함수

### 1. updated_at 자동 업데이트

```sql
CREATE OR REPLACE FUNCTION update_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 트리거 적용 (4개 테이블)
CREATE TRIGGER trigger_users_updated
    BEFORE UPDATE ON users
    FOR EACH ROW EXECUTE FUNCTION update_updated_at();

CREATE TRIGGER trigger_news_updated
    BEFORE UPDATE ON news_articles
    FOR EACH ROW EXECUTE FUNCTION update_updated_at();

CREATE TRIGGER trigger_stats_updated
    BEFORE UPDATE ON article_stats
    FOR EACH ROW EXECUTE FUNCTION update_updated_at();

CREATE TRIGGER trigger_preferences_updated
    BEFORE UPDATE ON user_preferences
    FOR EACH ROW EXECUTE FUNCTION update_updated_at();
```

### 2. search_vector 자동 생성

```sql
CREATE OR REPLACE FUNCTION update_search_vector()
RETURNS TRIGGER AS $$
BEGIN
    NEW.search_vector :=
        setweight(to_tsvector('simple', coalesce(NEW.title, '')), 'A') ||
        setweight(to_tsvector('simple', coalesce(NEW.ai_summary, '')), 'B') ||
        setweight(to_tsvector('simple', coalesce(NEW.content, '')), 'C');
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_search_vector
    BEFORE INSERT OR UPDATE ON news_articles
    FOR EACH ROW EXECUTE FUNCTION update_search_vector();
```

**가중치**:
- A (title): 최고 가중치
- B (ai_summary): 중간 가중치
- C (content): 낮은 가중치

### 3. article_stats 자동 업데이트

```sql
CREATE OR REPLACE FUNCTION update_article_stats()
RETURNS TRIGGER AS $$
BEGIN
    IF (TG_OP = 'INSERT') THEN
        -- 카운트 증가
        INSERT INTO article_stats (article_id,
            view_count, like_count, dislike_count, bookmark_count)
        VALUES (NEW.article_id,
            CASE WHEN NEW.action_type = 'VIEW' THEN 1 ELSE 0 END,
            CASE WHEN NEW.action_type = 'LIKE' THEN 1 ELSE 0 END,
            CASE WHEN NEW.action_type = 'DISLIKE' THEN 1 ELSE 0 END,
            CASE WHEN NEW.action_type = 'BOOKMARK' THEN 1 ELSE 0 END)
        ON CONFLICT (article_id) DO UPDATE SET
            view_count = article_stats.view_count +
                CASE WHEN NEW.action_type = 'VIEW' THEN 1 ELSE 0 END,
            like_count = article_stats.like_count +
                CASE WHEN NEW.action_type = 'LIKE' THEN 1 ELSE 0 END,
            dislike_count = article_stats.dislike_count +
                CASE WHEN NEW.action_type = 'DISLIKE' THEN 1 ELSE 0 END,
            bookmark_count = article_stats.bookmark_count +
                CASE WHEN NEW.action_type = 'BOOKMARK' THEN 1 ELSE 0 END,
            updated_at = NOW();
    END IF;
    RETURN NULL;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_stats_from_actions
    AFTER INSERT ON user_actions
    FOR EACH ROW EXECUTE FUNCTION update_article_stats();
```

## 뷰 (View)

### 1. v_news_detail (뉴스 상세)

```sql
CREATE OR REPLACE VIEW v_news_detail AS
SELECT
    a.id,
    a.title,
    a.content,
    a.ai_summary,
    a.url,
    a.image_url,
    s.name AS source_name,
    c.name AS category_name,
    a.journalist,
    a.pub_date,
    a.created_at,
    st.view_count,
    st.like_count,
    st.dislike_count,
    st.bookmark_count,
    st.comment_count,
    b.bias_score,
    b.political_leaning,
    b.confidence
FROM news_articles a
LEFT JOIN sources s ON a.source_id = s.id
LEFT JOIN categories c ON a.category_id = c.id
LEFT JOIN article_stats st ON a.id = st.article_id
LEFT JOIN bias_analysis b ON a.id = b.article_id;
```

### 2. v_trending_news (인기 뉴스)

```sql
CREATE OR REPLACE VIEW v_trending_news AS
SELECT
    a.id,
    a.title,
    a.ai_summary,
    s.name AS source_name,
    c.name AS category_name,
    st.view_count,
    st.like_count,
    (st.view_count * 0.5 + st.like_count * 2 - st.dislike_count) AS popularity_score
FROM news_articles a
JOIN article_stats st ON a.id = st.article_id
LEFT JOIN sources s ON a.source_id = s.id
LEFT JOIN categories c ON a.category_id = c.id
WHERE a.pub_date >= NOW() - INTERVAL '7 days'
ORDER BY popularity_score DESC;
```

### 3. v_user_activity_summary (사용자 활동 요약)

```sql
CREATE OR REPLACE VIEW v_user_activity_summary AS
SELECT
    u.id AS user_id,
    u.username,
    COUNT(DISTINCT CASE WHEN ua.action_type = 'VIEW' THEN ua.article_id END) AS articles_viewed,
    COUNT(DISTINCT CASE WHEN ua.action_type = 'LIKE' THEN ua.article_id END) AS articles_liked,
    COUNT(DISTINCT CASE WHEN ua.action_type = 'BOOKMARK' THEN ua.article_id END) AS articles_bookmarked,
    AVG(CASE WHEN ua.action_type = 'VIEW' THEN ua.reading_duration END) AS avg_reading_duration
FROM users u
LEFT JOIN user_actions ua ON u.id = ua.user_id
GROUP BY u.id, u.username;
```

## 데이터 흐름

### 크롤링 → 저장 → AI 처리

```
[1] 크롤러
    ↓
raw_news_articles
    - processed = FALSE
    ↓
[2] 스케줄러 (10분마다)
    ↓
분류 API
    ↓
news_articles
    - source_id, category_id 매핑
    ↓
요약 AI
    ↓
news_articles.ai_summary 업데이트
    ↓
편향성 분석 AI
    ↓
bias_analysis INSERT
    ↓
raw_news_articles.processed = TRUE
```

### 사용자 활동 → 통계 집계

```
사용자 행동 (조회/좋아요/북마크)
    ↓
user_actions INSERT
    ↓
트리거 발동
    ↓
article_stats 자동 업데이트
    (view_count, like_count 등 증가)
```
