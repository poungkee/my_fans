## 환경 개요

### 로컬 개발 환경

| 구성 요소 | 기술 스택 | 실행 방법 |
|---------|---------|---------|
| **데이터베이스** | PostgreSQL 15 | Docker Compose |
| **캐시** | Redis 7 | Docker Compose |
| **백엔드 API** | Node.js + TypeORM | Docker Compose |
| **AI 서비스** | Python + FastAPI | Docker Compose |
| **크롤러** | Node.js + TypeScript | Docker Compose |
| **스케줄러** | Node.js + node-cron | Docker Compose |
| **프론트엔드** | React 18 | 로컬 실행 (권장) |

**특징**:
- DB_SCHEMA: `development` 사용
- 모든 서비스 도커 컨테이너화
- 프론트엔드는 로컬 실행 권장 (HMR 지원)
- 30초마다 자동 크롤링 실행
- 10분마다 뉴스 처리 스케줄러 실행

### AWS EKS 운영 환경

| 구성 요소 | 스펙 | 비고 |
|---------|------|-----|
| **EKS Cluster** | Kubernetes 1.31 | fans-cluster |
| **Node Group** | t3.medium x 2 | Auto Scaling 1-3 |
| **RDS PostgreSQL** | db.t3.medium | Multi-AZ |
| **ElastiCache Redis** | cache.t3.micro | Single-AZ |
| **S3** | Standard | 프로필 이미지 저장 |
| **CloudFront** | 전세계 엣지 | 프론트엔드 배포 |
| **ALB** | Application LB | Ingress Controller |
| **Route 53** | fans.ai.kr | DNS 관리 |
| **ECR** | Private | 7개 이미지 저장소 |

**특징**:
- DB_SCHEMA: `production` 사용
- 스키마 분리로 개발/운영 완전 독립
- GitHub Actions 자동 배포
- Prometheus + Grafana 모니터링
- 고가용성: Multi-AZ 구성

```yaml
VPC CIDR: 10.0.0.0/16
```

```yaml
Node Group:
  이름: fans-private-medium
  인스턴스 타입: t3.medium (2 vCPU, 4GB RAM)
```

#### Terraform 주요 리소스

**EKS Cluster**:
```hcl
module "eks" {
  source  = "terraform-aws-modules/eks/aws"
  version = "~> 20.0"

  cluster_name    = "fans-cluster"
  cluster_version = "1.31"

  enable_irsa = true
  enable_cluster_creator_admin_permissions = true

  cluster_addons = {
    coredns            = { most_recent = true }
    kube-proxy         = { most_recent = true }
    vpc-cni            = { most_recent = true }
    aws-ebs-csi-driver = { most_recent = true }
  }
}
```

**Node Group**:
```hcl
eks_managed_node_groups = {
  medium = {
    name           = "fans-private-medium"
    instance_types = ["t3.medium"]
    capacity_type  = "ON_DEMAND"

    min_size     = 1
    max_size     = 3
    desired_size = 2

    disk_size = 30
    disk_type = "gp3"
  }
}
```

### 수동 배포 절차

#### 1. ECR 로그인

```bash
# AWS 계정 ID 확인
export AWS_ACCOUNT_ID=907123164281
export AWS_REGION=ap-northeast-2

# ECR 로그인
aws ecr get-login-password --region $AWS_REGION | \
  docker login --username AWS --password-stdin \
  $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com
```

#### 2. Docker 이미지 빌드

```bash
# Main API
docker build -t fans/main-api:latest \
  -f backend/api/Dockerfile \
  backend/api

# Summarize AI
docker build -t fans/summarize-ai:latest \
  -f backend/ai/summarize-ai/Dockerfile \
  backend/ai/summarize-ai

# Bias Analysis AI
docker build -t fans/bias-analysis-ai:latest \
  -f backend/ai/bias-analysis-ai/Dockerfile \
  backend/ai/bias-analysis-ai

docker build -t fans/classification-api:latest \
  -f backend/simple-classifier/Dockerfile \
  backend/simple-classifier

docker build -t fans/unified-crawler:latest \
  -f backend/crawler/crawler-v2/Dockerfile \
  backend/crawler/crawler-v2

# Scheduler
docker build -t fans/scheduler:latest \
  -f backend/scheduler/Dockerfile \
  backend/scheduler

# Frontend (CloudFront 배포 대신)
docker build -t fans/frontend:latest \
  -f frontend/Dockerfile \
  frontend
```

#### 3. ECR에 푸시

```bash
# 이미지 태그 지정 및 푸시 (Main API 예시)
docker tag fans/main-api:latest \
  $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/fans/main-api:latest

docker push $AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/fans/main-api:latest

# 다른 서비스도 동일하게 반복
```

#### 4. EKS 클러스터 연결

```bash

  --name fans-cluster \
  --region ap-northeast-2
```

#### 5. Kubernetes 배포


## GitHub Actions CI/CD

### 워크플로우 개요

파일: `.github/workflows/deploy-eks.yml`

**트리거**:
- `main` 브랜치에 push
- 수동 실행 (`workflow_dispatch`)

**빌드 대상 서비스** (7개):
1. Main API (Node.js)
2. Summarize AI (Python/FastAPI)
3. Bias Analysis AI (Python/FastAPI)
4. Classification API (Python/Flask)
5. Unified Crawler (Node.js)
6. Scheduler (Node.js)
7. Frontend (React)

### 배포 프로세스

```
1. 코드 체크아웃
   └─> actions/checkout@v3

2. AWS 인증
   └─> aws-actions/configure-aws-credentials@v2
       ├─> AWS_ACCESS_KEY_ID
       └─> AWS_SECRET_ACCESS_KEY

3. ECR 로그인
   └─> aws-actions/amazon-ecr-login@v1

4. 이미지 태그 생성
   └─> Git SHA 앞 7자리 (예: a1b2c3d)

5. Docker 이미지 빌드 (병렬)
   ├─> Main API
   ├─> Summarize AI
   ├─> Bias Analysis AI
   ├─> Classification API
   ├─> Unified Crawler
   ├─> Scheduler
   └─> Frontend

6. ECR 푸시 (각 서비스)
   ├─> fans/main-api:a1b2c3d
   ├─> fans/main-api:latest
   └─> ... (다른 서비스 동일)

7. kubectl 설정
   └─> aws eks update-kubeconfig

8. Deployment 이미지 업데이트
   └─> kubectl set image deployment/...

9. 매니페스트 적용
   └─> kubectl apply -f environments/eks/manifests/

10. 롤아웃 상태 확인
    ├─> kubectl rollout status deployment/main-api
    ├─> kubectl rollout status deployment/summarize-ai
    └─> kubectl rollout status deployment/bias-analysis-ai

11. 배포 확인
    ├─> kubectl get pods -n fans
    ├─> kubectl get svc -n fans
    └─> kubectl get ingress -n fans

12. Slack 알림 (선택사항)
    └─> 8398a7/action-slack@v3
```

### 알림 규칙

**파일**: `environments/eks/manifests/12-prometheus-alerts.yaml`

#### 설정된 알림 목록

| 알림 이름 | 조건 | 심각도 | 지속 시간 |
|----------|------|--------|----------|
| **PodPending** | Pod가 Pending 상태 | warning | 5분 |
| **PodHighCPU** | Pod CPU 사용률 > 80% | warning | 5분 |
| **PodHighMemory** | Pod 메모리 사용률 > 80% | warning | 5분 |
| **PodRestarting** | Pod 재시작 발생 | warning | 1분 |
| **PodCrashLoopBackOff** | Pod CrashLoopBackOff 상태 | critical | 1분 |
| **NodeHighCPU** | 노드 CPU 사용률 > 85% | warning | 10분 |
| **NodeHighMemory** | 노드 메모리 사용률 > 85% | warning | 10분 |
| **NodeHighDiskUsage** | 노드 디스크 사용률 > 85% | warning | 10분 |
| **DeploymentReplicasMismatch** | Deployment 레플리카 불일치 | warning | 15분 |

#### 알림 규칙 예시

```yaml
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: fans-alerts
  namespace: monitoring
spec:
  groups:
  - name: fans.rules
    interval: 30s
    rules:
    - alert: PodHighCPU
      expr: |
        sum(rate(container_cpu_usage_seconds_total{namespace="fans", pod!=""}[5m])) by (pod) * 100 > 80
      for: 5m
      labels:
        severity: warning
      annotations:
        summary: "Pod {{ $labels.pod }} high CPU usage"
        description: "Pod {{ $labels.pod }} CPU usage is {{ $value }}%"

    - alert: PodCrashLoopBackOff
      expr: |
        kube_pod_container_status_waiting_reason{namespace="fans", reason="CrashLoopBackOff"} == 1
      for: 1m
      labels:
        severity: critical
      annotations:
        summary: "Pod {{ $labels.pod }} in CrashLoopBackOff"
        description: "Pod {{ $labels.pod }} is in CrashLoopBackOff state"
```

```
Inbound:
  - All traffic from ALB Security Group

Outbound:
  - All traffic to 0.0.0.0/0
```

```
Inbound:
  - PostgreSQL (5432) from Node Security Group

Outbound:
  - (없음)
```
