## 환경 개요

### 로컬 개발 환경

| 구성 요소 | 기술 스택 | 실행 방법 |
|---------|---------|---------|
| **데이터베이스** | PostgreSQL 15 | Docker Compose |
| **캐시** | Redis 7 | Docker Compose |
| **백엔드 API** | Node.js + TypeORM | Docker Compose |
| **AI 서비스** | Python + FastAPI | Docker Compose |
| **크롤러** | Node.js + TypeScript | Docker Compose |
| **스케줄러** | Node.js + node-cron | Docker Compose |
| **프론트엔드** | React 18 | 로컬 실행 (권장) |

**특징**:
- DB_SCHEMA: `development` 사용
- 모든 서비스 도커 컨테이너화
- 프론트엔드는 로컬 실행 권장 (HMR 지원)
- 30초마다 자동 크롤링 실행
- 10분마다 뉴스 처리 스케줄러 실행

### AWS EKS 운영 환경

| 구성 요소 | 스펙 | 비고 |
|---------|------|-----|
| **EKS Cluster** | Kubernetes 1.31 | fans-cluster |
| **Node Group** | t3.medium x 2 | Auto Scaling 1-3 |
| **RDS PostgreSQL** | db.t3.medium | Multi-AZ |
| **ElastiCache Redis** | cache.t3.micro | Single-AZ |
| **S3** | Standard | 프로필 이미지 저장 |
| **CloudFront** | 전세계 엣지 | 프론트엔드 배포 |
| **ALB** | Application LB | Ingress Controller |
| **Route 53** | fans.ai.kr | DNS 관리 |
| **ECR** | Private | 6개 이미지 저장소 |
| **KEDA** | v2.14+ | AI Worker 오토스케일링 |

**배포된 서비스** (6개 Deployment):
1. main-api (2 replicas) - Main API Server
2. unified-crawler (1 replica) - 통합 크롤러
3. scheduler (2 replicas) - 뉴스 처리 스케줄러
4. ai-worker (2~20 replicas) - AI 작업 워커 (KEDA 오토스케일링)
5. summarize-ai (2 replicas) - 요약 AI 서비스
6. bias-analysis-ai (2 replicas) - 편향 분석 AI 서비스

**배치 작업** (2개 CronJob):
1. batch-summary-backlog - 과거 기사 요약 백로그 처리 (매일 새벽 2시)
2. db-backup-to-school - 학교 서버 DB 백업 (매일 새벽 2시)

**특징**:
- DB_SCHEMA: `production` 사용
- 스키마 분리로 개발/운영 완전 독립
- GitHub Actions 자동 배포
- Prometheus + Grafana 모니터링
- 고가용성: Multi-AZ 구성
- KEDA 기반 Redis 큐 오토스케일링

#### Terraform 주요 리소스

**EKS Cluster**:
```hcl
module "eks" {
  source  = "terraform-aws-modules/eks/aws"
  version = "~> 20.0"

  cluster_name    = "fans-cluster"
  cluster_version = "1.31"

  enable_irsa = true
  enable_cluster_creator_admin_permissions = true

  cluster_addons = {
    coredns            = { most_recent = true }
    kube-proxy         = { most_recent = true }
    vpc-cni            = { most_recent = true }
    aws-ebs-csi-driver = { most_recent = true }
  }
}
```

**Node Group**:
```hcl
eks_managed_node_groups = {
  medium = {
    name           = "fans-private-medium"
    instance_types = ["t3.medium"]
    capacity_type  = "ON_DEMAND"

    min_size     = 1
    max_size     = 3
    desired_size = 2

    disk_size = 30
    disk_type = "gp3"
  }
}
```


### 알림 규칙

**파일**: `environments/eks/manifests/12-prometheus-alerts.yaml`

#### 설정된 알림 목록

| 알림 이름 | 조건 | 심각도 | 지속 시간 |
|----------|------|--------|----------|
| **PodPending** | Pod가 Pending 상태 | warning | 5분 |
| **PodHighCPU** | Pod CPU 사용률 > 80% | warning | 5분 |
| **PodHighMemory** | Pod 메모리 사용률 > 80% | warning | 5분 |
| **PodRestarting** | Pod 재시작 발생 | warning | 1분 |
| **PodCrashLoopBackOff** | Pod CrashLoopBackOff 상태 | critical | 1분 |
| **NodeHighCPU** | 노드 CPU 사용률 > 85% | warning | 10분 |
| **NodeHighMemory** | 노드 메모리 사용률 > 85% | warning | 10분 |
| **NodeHighDiskUsage** | 노드 디스크 사용률 > 85% | warning | 10분 |
| **DeploymentReplicasMismatch** | Deployment 레플리카 불일치 | warning | 15분 |
| **RedisQueueBacklog** | Redis 큐 길이 > 500 | warning | 5분 |
| **CronJobFailed** | CronJob 실행 실패 | critical | 1분 |
| **KEDAScalerNotReady** | KEDA ScaledObject 비정상 | critical | 5분 |

#### 알림 규칙 예시

```yaml
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: fans-alerts
  namespace: monitoring
spec:
  groups:
  - name: fans.rules
    interval: 30s
    rules:
    - alert: PodHighCPU
      expr: |
        sum(rate(container_cpu_usage_seconds_total{namespace="fans", pod!=""}[5m])) by (pod) * 100 > 80
      for: 5m
      labels:
        severity: warning
      annotations:
        summary: "Pod {{ $labels.pod }} high CPU usage"
        description: "Pod {{ $labels.pod }} CPU usage is {{ $value }}%"

    - alert: PodCrashLoopBackOff
      expr: |
        kube_pod_container_status_waiting_reason{namespace="fans", reason="CrashLoopBackOff"} == 1
      for: 1m
      labels:
        severity: critical
      annotations:
        summary: "Pod {{ $labels.pod }} in CrashLoopBackOff"
        description: "Pod {{ $labels.pod }} is in CrashLoopBackOff state"
```

### CronJob 문제

#### CronJob 실행 안됨

**증상**:
```
kubectl get cronjobs -n fans
NAME                     SCHEDULE      SUSPEND   ACTIVE   LAST SCHEDULE   AGE
batch-summary-backlog    0 17 * * *    False     0        <none>          1d
```

**원인**:
- 시간대 설정 오류 (UTC vs KST)
- CronJob이 suspend 상태
- 이전 Job이 아직 실행 중 (concurrencyPolicy: Forbid)

**해결**:
```bash
# CronJob 상세 정보 확인
kubectl describe cronjob batch-summary-backlog -n fans

# Suspend 확인
kubectl get cronjob batch-summary-backlog -n fans -o jsonpath='{.spec.suspend}'

# 수동 실행 (테스트)
kubectl create job --from=cronjob/batch-summary-backlog manual-test -n fans

# 이전 Job 확인
kubectl get jobs -n fans -l app=batch-summary-backlog

# 스케줄 수정 (한국 시간 새벽 2시 = UTC 17시)
kubectl edit cronjob batch-summary-backlog -n fans
```

#### CronJob Job 실패

**증상**:
```
kubectl get jobs -n fans
NAME                            COMPLETIONS   DURATION   AGE
batch-summary-backlog-28412790  0/1           5m         5m
```

**원인**:
- DB 연결 실패
- Redis 연결 실패
- 배치 스크립트 오류
- 리소스 부족

**해결**:
```bash
# Job 로그 확인
kubectl logs job/batch-summary-backlog-28412790 -n fans

# Pod 상태 확인
kubectl get pods -n fans -l job-name=batch-summary-backlog-28412790
kubectl describe pod batch-summary-backlog-28412790-xyz -n fans

# Job 재실행
kubectl delete job batch-summary-backlog-28412790 -n fans
kubectl create job --from=cronjob/batch-summary-backlog retry-$(date +%s) -n fans

# 실패한 Job 전체 삭제
kubectl delete job -n fans --field-selector status.successful=0
```
