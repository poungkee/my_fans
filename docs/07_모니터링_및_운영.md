## 🔔 알림 규칙 (Alert Rules)

### 설정된 알림 목록

**파일 위치**: `environments/eks/manifests/12-prometheus-alerts.yaml`

| 알림 이름 | 조건 | 심각도 | 지속 시간 |
|----------|------|-------|----------|
| **PodPending** | Pod가 Pending 상태 | warning | 5분 |
| **PodHighCPU** | Pod CPU 사용률 > 80% | warning | 5분 |
| **PodHighMemory** | Pod 메모리 사용률 > 80% | warning | 5분 |
| **PodRestarting** | Pod 재시작 발생 | warning | 1분 |
| **PodCrashLoopBackOff** | Pod CrashLoopBackOff 상태 | critical | 1분 |
| **NodeHighCPU** | 노드 CPU 사용률 > 85% | warning | 10분 |
| **NodeHighMemory** | 노드 메모리 사용률 > 85% | warning | 10분 |
| **NodeHighDiskUsage** | 노드 디스크 사용률 > 85% | warning | 10분 |
| **DeploymentReplicasMismatch** | Deployment 레플리카 불일치 | warning | 15분 |

### 알림 확인

```bash
# Prometheus에서 알림 상태 확인
kubectl port-forward -n monitoring svc/prometheus-kube-prometheus-prometheus 9090:9090

# 브라우저에서 http://localhost:9090/alerts 접속
```

### 알림 규칙 수정

```bash
# 알림 규칙 파일 수정
nano environments/eks/manifests/12-prometheus-alerts.yaml

# 적용
kubectl apply -f environments/eks/manifests/12-prometheus-alerts.yaml

# 확인
kubectl get prometheusrules -n monitoring fans-alerts
```

## 📈 주요 모니터링 메트릭

### Pod 메트릭

```promql
# Pod CPU 사용률
sum(rate(container_cpu_usage_seconds_total{namespace="fans", pod!=""}[5m])) by (pod) * 100

# Pod 메모리 사용량
sum(container_memory_working_set_bytes{namespace="fans", pod!=""}) by (pod)

# Pod 재시작 횟수
rate(kube_pod_container_status_restarts_total{namespace="fans"}[15m])

# Pod 상태
kube_pod_status_phase{namespace="fans"}
```

### Node 메트릭

```promql
# Node CPU 사용률
100 - (avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

# Node 메모리 사용률
100 * (1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes))

# Node 디스크 사용률
100 - ((node_filesystem_avail_bytes{mountpoint="/"} * 100) / node_filesystem_size_bytes{mountpoint="/"})
```

## 🛠️ 운영 작업

### NodeGroup 스케일 조정

비용 절감을 위해 NodeGroup을 축소하거나 확장할 수 있습니다.

```bash
# NodeGroup 축소 (비용 절감)
cd environments/eks/scripts
./scale-nodegroup.sh stop

# NodeGroup 재시작
./scale-nodegroup.sh start
```

**주의사항**:
- NodeGroup을 0으로 축소해도 EKS 컨트롤 플레인, RDS, ALB, NAT Gateway는 계속 과금됩니다
- 축소 시 모든 Pod가 종료됩니다
- 재시작 후 Pod가 준비되는 데 2-3분 소요됩니다

### Pod 재시작

```bash
# 특정 Deployment 재시작
kubectl rollout restart deployment/main-api -n fans
kubectl rollout restart deployment/summarize-ai -n fans

# 재시작 상태 확인
kubectl rollout status deployment/main-api -n fans
```

### 로그 확인

```bash
# Pod 로그 실시간 확인
kubectl logs -f deployment/main-api -n fans

# 여러 Pod 로그 동시 확인
kubectl logs -f deployment/main-api -n fans --all-containers=true

# 이전 컨테이너 로그 확인 (재시작된 경우)
kubectl logs deployment/main-api -n fans --previous

# 최근 100줄만 확인
kubectl logs --tail=100 deployment/main-api -n fans
```

### 리소스 사용 현황

```bash
# Pod 리소스 사용량
kubectl top pods -n fans

# Node 리소스 사용량
kubectl top nodes

# 상세 Pod 정보
kubectl describe pod <pod-name> -n fans
```

## 🔍 트러블슈팅

### Pod가 Pending 상태일 때

```bash
# Pod 상세 정보 확인
kubectl describe pod <pod-name> -n fans

# 일반적인 원인:
# 1. 노드에 리소스 부족 → NodeGroup 확장
# 2. PVC 마운트 실패 → StorageClass 확인
# 3. 이미지 풀 실패 → ECR 권한 확인
```

### Pod가 CrashLoopBackOff일 때

```bash
# 로그 확인
kubectl logs <pod-name> -n fans

# 이전 컨테이너 로그 확인
kubectl logs <pod-name> -n fans --previous

# 일반적인 원인:
# 1. 애플리케이션 오류 → 로그 확인
# 2. 환경 변수 누락 → ConfigMap/Secret 확인
# 3. DB 연결 실패 → RDS 보안 그룹 확인
```

### 서비스 접속 불가

```bash
# Service 확인
kubectl get svc -n fans

# Ingress 확인
kubectl get ingress -n fans
kubectl describe ingress fans-ingress -n fans

# ALB 상태 확인
kubectl describe service main-api -n fans

# 일반적인 원인:
# 1. ALB 타겟 그룹 Unhealthy → Pod 상태 확인
# 2. Route53 레코드 오류 → DNS 설정 확인
# 3. SSL 인증서 문제 → ACM 인증서 확인
```

### 현재 리소스별 예상 비용 (월간)

| 리소스 | 수량 | 단가 | 월 비용 |
|-------|------|------|--------|
| **EKS 컨트롤 플레인** | 1 | $0.10/시간 | $73 |
| **EC2 (t3.medium)** | 2 | $0.0416/시간 | $60 |
| **EC2 (t3.large)** | 2 | $0.0832/시간 | $120 |
| **RDS (db.t3.medium)** | 1 | $0.068/시간 | $49 |
| **NAT Gateway** | 2 | $0.059/시간 | $85 |
| **ALB** | 1 | $0.0252/시간 | $18 |
| **EBS (gp3)** | 100GB | $0.08/GB | $8 |
| **S3** | 10GB | $0.023/GB | $0.23 |
| **CloudFront** | 1 | 데이터 전송량 | $5-10 |
| **합계** | | | **$418-423/월** |

### 비용 절감 방법

1. **NodeGroup 축소**: 사용하지 않을 때 NodeGroup을 0으로 축소 (54% 절감)
2. **RDS 중지**: 개발 환경에서는 RDS를 중지할 수 있음 (최대 7일)
3. **NAT Gateway 제거**: Private 서브넷 대신 Public 서브넷 사용 (비권장)
4. **Spot Instance 사용**: On-Demand 대신 Spot Instance 사용 (최대 90% 절감)

kubectl exec -it -n monitoring <grafana-pod-name> -- /bin/sh

```bash
# 현재 7일 설정되어 있음

helm upgrade prometheus prometheus-community/kube-prometheus-stack \
  --namespace monitoring \
  --set prometheus.prometheusSpec.retention=14d
```
