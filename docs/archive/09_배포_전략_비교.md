## 전략별 작동 방식

### 1. Rolling Update (현재 사용 중)

```
시작:  [V1] [V1] [V1] [V1]  ◄─ 100% 구버전
        │
Step 1: [V1] [V1] [V1] [V2]  ◄─ V2 시작, V1 하나 종료
        │
Step 2: [V1] [V1] [V2] [V2]  ◄─ 점진적 교체
        │
Step 3: [V1] [V2] [V2] [V2]
        │
완료:   [V2] [V2] [V2] [V2]  ◄─ 100% 신버전

⏱️ 소요 시간: 5-10분
💰 추가 비용: ~0% (maxSurge 1개만)
```

**장점**
- ✅ 추가 리소스 거의 불필요 (비용 최소)
- ✅ Kubernetes 기본 기능 (별도 도구 불필요)
- ✅ 설정 간단 (YAML 몇 줄)

**단점**
- ❌ 롤백 느림 (5-10분)
- ❌ 50% 사용자가 버그 경험 가능
- ❌ 트래픽 비율 조절 불가

---

### 2. Canary Deployment

```
시작:  [V1] [V1] [V1] [V1]  ◄─ 100% V1 트래픽
        │
Step 1: [V1] [V1] [V1] [V1] [V2]
        └────80%────┘       └20%┘  ◄─ 20% 사용자만 V2
        ⏱️ 5분 대기 + 메트릭 확인
        │
Step 2: [V1] [V1] [V2] [V2]
        └─50%─┘  └─50%─┘  ◄─ 50% vs 50%
        ⏱️ 5분 대기 + 메트릭 확인
        │
Step 3: [V1] [V2] [V2] [V2]
        └25%┘ └───75%───┘  ◄─ 75% V2로 확대
        ⏱️ 5분 대기 + 메트릭 확인
        │
완료:   [V2] [V2] [V2] [V2]  ◄─ 100% V2

⏱️ 소요 시간: 20-30분 (안전하게)
💰 추가 비용: +3% (배포 중 추가 Pod)

📊 자동 롤백 조건:
  - 에러율 > 5% → 즉시 중단
  - 응답시간 > 2초 → 즉시 중단
  - 성공률 < 95% → 즉시 중단
```

**장점**
- ✅ 점진적 노출 (20% → 50% → 100%)
- ✅ 자동 롤백 (Prometheus 메트릭 기반)
- ✅ 리스크 최소화 (소수 사용자만 영향)
- ✅ A/B 테스트 가능

**단점**
- ❌ Argo Rollouts 학습 필요
- ❌ Prometheus 메트릭 필수
- ❌ 배포 시간 길어짐 (20-30분)

---

### 3. Blue/Green Deployment

```
Step 1: Blue 환경 (현재)
        [V1] [V1] [V1] [V1]  ◄─ 100% 프로덕션 트래픽

        Green 환경 (신규 배포)
        [V2] [V2] [V2] [V2]  ◄─ 0% 트래픽 (대기)

        ⏱️ Green 테스트 중...
        curl http://main-api-preview:3000

Step 2: 트래픽 전환 (즉시)
        [V1] [V1] [V1] [V1]  ◄─ 0% 트래픽 (대기)
        [V2] [V2] [V2] [V2]  ◄─ 100% 트래픽 ✅

        문제 발생 시? → 1초 만에 Blue로 복귀!

Step 3: Blue 삭제 (5분 후)
        [V2] [V2] [V2] [V2]  ◄─ 100% 트래픽

⏱️ 전환 시간: 1초 (즉시)
💰 추가 비용: +20% (리소스 2배)
```

**장점**
- ✅ 즉시 롤백 (1초)
- ✅ 완전한 테스트 후 전환
- ✅ 위험 최소화
- ✅ 예측 가능한 배포

**단점**
- ❌ 리소스 2배 필요 (비용 증가)
- ❌ DB 마이그레이션 복잡
- ❌ 배포 중 리소스 낭비
