## 현재 아키텍처 요약

### 인프라
- **EKS 클러스터**: fans-cluster-2az (Kubernetes v1.31)
- **가용 영역**: 2 AZs (ap-northeast-2a, ap-northeast-2c)
- **워커 노드**: 4개
  - t3.medium × 2
  - t3.large × 2
- **RDS**: PostgreSQL 15.10 (db.t3.medium, 20GB)

### 네트워킹
- **Public Subnets**: ALB, NAT Gateway
- **Private Subnets**: EKS Worker Nodes
- **Ingress**: ALB를 통한 api.fans.ai.kr 라우팅
- **Frontend**: CloudFront + S3 (www.fans.ai.kr)

### 애플리케이션
- **총 Pod 수**: 13개 (모두 Running)
- **서비스**: 7개 마이크로서비스
  - main-api (2 replicas): 메인 API, OAuth 인증
  - summarize-ai (2 replicas): 뉴스 요약 AI
  - bias-analysis-ai (2 replicas): 편향성 분석 AI
  - classification-api (2 replicas): 뉴스 분류 AI
  - unified-crawler (1 replica): 뉴스 크롤러
  - scheduler (1 replica): 뉴스 처리 스케줄러
  - redis (1 replica): 세션 & 캐시

### 도메인
- **api.fans.ai.kr** → ALB → main-api-service
- **www.fans.ai.kr** → CloudFront → S3
- **fans.ai.kr** → CloudFront

### IAM & 보안
- EKS 노드에 S3 업로드 권한 부여 (FANS-S3-ProfileImages-Upload)
- SSL/TLS: ACM 인증서 (CloudFront, ALB)
- RDS SSL 연결 활성화

### 데이터 플로우
1. 사용자 → CloudFront → S3 (프론트엔드)
2. 프론트엔드 → ALB → main-api (인증, API)
3. main-api → RDS (데이터베이스)
4. main-api → Redis (세션)
5. main-api → AI 서비스 (요약, 분류, 편향성 분석)
6. crawler → RDS (뉴스 수집)
7. scheduler → AI 서비스 → RDS (자동 처리)
